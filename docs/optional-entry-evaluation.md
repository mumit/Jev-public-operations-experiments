# Compare optional suggestions with entry alone

This is a proposed usability comparison, not an executed or frozen experiment. The first-question policy failed its model coverage requirements. A participant comparison would test whether its optional advice helps entry despite those misses; it would not promote the model or replace the failed result.

## The comparison

One participant can start with a short usability walkthrough. That can expose confusing questions, extra work or misleading confidence. A comparative performance claim needs a separate task allocation and more participants; a walkthrough alone supplies neither.

If selected, the next protocol will freeze a new controlled task pack, explicit reference fields, expected clarification responses, assignment and scoring before recording activity. Each task will supply the incident comparison and service/channel catalog. Missing information must be obtained through a scripted clarification response or left unresolved, rather than guessed. References will remain assistant-authored unless a separate reviewer contributes them.

Both conditions require the same five manual selections and exact numerical policy. Entry alone supplies the form. The assisted condition adds the frozen six-question Jev input and first-question display policy. It cannot prefill a field or clear a claim. Distinct but matched tasks and counterbalanced condition order will limit repeated-task learning. Every participant must see the same task instructions; coaching and reference reveal occur after a scored attempt.

## What to record

| Outcome | Meaning |
| --- | --- |
| Correct completed entry | Explicit fields match the frozen task reference |
| Unresolved task | Required information or a selection remains missing |
| Wrong entry | A completed field set differs from the reference |
| Completion time | Time from task presentation to explicit submit or withhold |
| Clarification burden | Questions asked, including unnecessary questions |
| Usefulness | Participant explanation of what helped or interrupted the task |

Keep every attempted task, withheld suggestion and unresolved entry in the denominator. Separate software failures from entry errors. Report participant counts and individual observations before making aggregate claims. These outcomes do not measure telecom incident resolution or authentic-report accuracy.

## The dependency

A person needs to perform the tasks to measure entry behavior and effort. Assistant fixtures and browser verification can check software, but cannot supply participant evidence. The current inspector remains an unrecorded local prototype. No participant data, elapsed-time result, new task pack or additional inference exists yet.
