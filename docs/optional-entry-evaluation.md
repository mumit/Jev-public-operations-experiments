# Try entry alone and entry with optional suggestions

The user selected a short usability walkthrough. The task pack is prepared; no participant results have been received. The first-question policy still fails its model coverage requirements. This walkthrough asks whether its optional questions help someone complete explicit entries despite those misses.

## Take the walkthrough

Open [the entry walkthrough](http://127.0.0.1:8769/entry-walkthrough). Allow about 10–15 minutes.

1. Start with two practice tasks. They explain the fields and give immediate feedback; they do not enter the comparison.
2. Start the eight tasks. Read each statement, then select service, metric channel, comparison, assertion and time window. Every field starts blank.
3. Use **Ask the source** when a detail is unclear. The reply supplies information, but you make every selection yourself. Some tasks also show a recorded Jev question, which may help or miss a needed detail.
4. Submit once, or withhold an unresolved task. Add an optional note after completing it. Reference feedback appears after all eight tasks.
5. Choose **Export private results** and share the JSON file here if you want it analyzed. Exporting does not upload anything.

Pause whenever needed. Progress saves in this browser and resumes after a reload. Keeping the same browser and address preserves the session. If browser storage fails, the page warns you to keep it open and export before leaving. An export of unfinished progress retains finalized tasks and the current entry; incomplete tasks remain in the assigned denominator.

## What is fixed

The comparison contains four tasks with entry alone and four with optional suggestions, in the order A, B, B, A, B, A, A, B. Each condition contains two Train Ticket and two Online Boutique tasks, covering explicit magnitude, omitted service, omitted metric and vague comparison. Both conditions offer the same five source-question buttons and require the same five manual selections.

The eight statements come from the already inspected optional-question study. This is a purposeful sample selected after its results, not fresh wording or a random sample. I added complete reference entries, scripted source replies and two separate practice tasks before participant activity. The earlier study's first round supplies every recorded suggestion; no favorable round is selected per task. The pack fingerprints each original request and response row.

The plan and pack are committed separately. A final protocol fingerprints the pack, task order and four interface files before normal participant access. The page verifies that protocol and refuses a changed interface. Software preview uses separate local storage and exports marked `assistant_preview`; normal assessment rejects those exports.

No new model inference, measurements or protected recordings are needed. The page records the requested check; it supplies no numerical verdict and fills no field automatically.

## How results will be read

| Outcome | Meaning |
| --- | --- |
| Grounded correct entry | All five selections match the reference, and every required missing detail was requested from the source |
| Matching guess | Selections match, but a required source clarification was not requested |
| Wrong entry | A submitted field set differs from the reference |
| Withheld task | The participant stops without submitting a completed entry |
| Unrecorded task | An assigned task has no finalized record yet |
| Source questions | All requests, including repeated or unnecessary ones |
| Foreground time | Browser activity time before submit or withhold, excluding reported pauses and focus loss |
| Usefulness and comments | Optional feedback after finalizing a task, excluded from completion timing |

Every assigned task stays in the denominator. Wall time and interruptions accompany foreground time in the private export. Browser timing is a proxy for page activity, not cognitive effort. Partial exports do not establish completion, and matching guesses do not count as grounded correct entries.

## What this can establish

A single walkthrough can expose confusing wording, extra questions, incorrect entries or misleading suggestions. It cannot establish a causal time saving, authentic-report accuracy or operational reliability. The tasks and references share an assistant author, the participant is unblinded, and experience can carry between tasks despite the interleaved order. Full reference entries are hidden during the interface flow, but that is not secure blinding: the repository and earlier inspectors remain available.

Participant exports stay private and outside the repository and public evidence releases. The server receives no selections, questions, timing or comments. A submitted export is self-declared participation, not verified identity or independent specialist review. Software fixtures and browser checks remain separate from participant evidence.

After an actual export arrives, validation will check the frozen protocol, task order, fields and timing before describing outcomes by condition. The next decision should follow those observations; this preparation adds no measured human benefit and does not replace the failed model gates.
